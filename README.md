# OnlyBudget

A minimal, honest budgeting app. No bank sync, no accounts, no ads, no bait-and-switch subscriptions. You speak or type your income, expenses and goals in plain language, and the app does the categorizing for you.

```
"spent 12 dollars on lunch"        → $12 · Money out · Dining out · today
"got paid 2400"                     → $2,400 · Money in · Salary
"goal: save 500 for a trip by dec"  → Goal: Trip, $500 by December 31
"add 100 to the trip goal"          → +$100 toward Trip (logged as a transfer)
"remind me to pay rent on the 1st"  → Reminder: Pay rent, Oct 1 at 09:00
"how much did I spend on coffee this week?" → "This week you've spent $14.37 on coffee, across 2 entries."
```

Questions are answered, never saved. "This week" runs from Sunday to today. Ask by voice and the answer is read back aloud with the phone's own voices; type it and it stays on screen. Settings → Answers to questions changes that.

## Principles (non-negotiable)

1. **No bank linking, ever.** Not as a feature, not as an upsell.
2. **Voice and text are equal.** Both go through the same parser and the same confirmation card.
3. **No dark patterns.** No trials that flip into subscriptions. Nothing the user entered is ever paywalled.
4. **Local-first.** SQLite on the device. Works with zero network. Export and encrypted backup from day one.
5. **Calm, not gamified.** Plain sentences, no streaks, no red badges.

## Languages

The app speaks eight languages: English, Spanish, French, Italian, German, Chinese (Simplified), Japanese, and Korean. It follows the phone's language by default and can be switched in Settings. Each language has:

- a full UI string table and plain-language sentence set (`src/i18n/locales/<code>.ts`),
- a parser language pack with its own number words, verbs, category keywords, date phrases, and goal patterns (`src/parser/packs/<code>.ts`),
- locale-correct money and date formatting (`1.234,50 €`, `¥1,200`, `9月3日`),
- the matching speech-recognizer locale.

Chinese, Japanese, and Korean use substring matching instead of word tokens, convert native numerals (十二, 1万2千, 2만5천), and learn whole phrases from corrections. Adding a language is two files plus a line in each registry.

## Stack

- React Native + Expo SDK 57, TypeScript, expo-router
- `expo-sqlite` for storage, `zustand` for state, `expo-localization` for the phone's language
- `expo-speech-recognition` (platform-native, on-device where supported) for voice
- `expo-file-system` + `expo-sharing` for export; `@noble/ciphers` + `@noble/hashes` for passphrase-encrypted backups
- No backend. An optional Tier 2 parsing assist (the user's own Anthropic key, off by default) exists in the code but is held back from 1.0 by `SMART_ASSIST` in `src/lib/features.ts`, so the shipped app makes no network request.

## Running it

Voice and SQLite are native modules, so use a development build rather than Expo Go.

```bash
npm install
npx expo run:ios        # or: npx expo run:android
```

The native `ios/` and `android/` folders are generated by `expo prebuild` and are git-ignored.

Web build and containers (optional; the phone builds are the product):

```bash
npm run web         # dev server in the browser (Chrome/Edge for voice)
npm run build:web   # static web build in dist/ with PWA manifest and service worker
podman build -t onlybudget-web . && podman run --rm -p 8080:8080 onlybudget-web
```

See [docs/CONTAINERS.md](docs/CONTAINERS.md) for Podman, Kubernetes and OpenShift deployment, and for building the Android APK inside a container.

Checks:

```bash
npm test          # jest: parser (8 languages), plain-language, i18n formatting, recurring, export, crypto
npm run typecheck # tsc --noEmit
npm run icons     # regenerate assets/*.png from scripts/generate-icons.js
```

Looking at the real UI (each needs `npm run build:web` first; headless Chromium drives the web build, which uses the same components as the phone apps):

```bash
npm run ui:shots        # every screen at phone and tablet sizes, out/shots
npm run ui:walkthrough  # 28 flows (edit, undo, questions, goals, import, backup, languages…), logs any page error, out/walk
npm run ui:scenario     # pay periods, roll-over, the overall plan and undo with months of sample data, out/scenario
npm run ui:persona      # a voice in use: onboarding, each voice after an entry, the rules that keep it kind, out/persona
npm run ui:sweep        # every screen, phone and tablet, light and dark, with a goal, a reminder and debts seeded, out/sweep
```

Spending is also split three ways on the Budget tab, in priority order: needs, debts and wants. Those are the buckets of the 50/30/20 rule, so most people already know them. Every category starts in a sensible tier, so there is nothing to set up. The app shows the split and never tells anyone what to cut.

The sample data used by these scripts never ships: it exists only in `scripts/lib/shots.mjs` and enters a browser session through the app's own backup restore. `__tests__/release.test.ts` checks that app code carries none of it and that the database migrations insert only categories and settings. In-app instructions live under Settings → Help, in all eight languages.

## How parsing works

**Tier 1 (always, offline, instant)** in `src/parser/`, driven by the active language pack:

- Number words → digits (`twelve dollars`, `doscientos cincuenta`, `zweihundertfünfzig`, `一千二百`, `2만5천`, `2.4k`).
- Date phrases are pulled out first so `sept 3` is never mistaken for an amount (`yesterday`, `last friday`, `on the 1st`, `3 days ago`, `9/3`).
- Amount: prefers a number with a currency marker, else the first bare number; ordinals, times and percentages are skipped.
- Type: income verbs (`got paid`, `earned`, `refund`…) vs expense verbs (`spent`, `paid`, `bought`…). If neither, the category decides; if nothing, expense with a hint.
- Category: learned words (from user corrections) → custom category names → the pack's keyword dictionary, longest phrase first (`gas bill` beats `gas`; `电影` beats `电`).
- Goals: `goal: …`, `save X for Y by Z`, `I want to save…`, `Set a goal of $10,000 for a trip to Hawaii in Oct 2027`. Contributions to an existing goal: `add 100 to the trip goal`, `put 50 toward japan`.
- Pay-down goals: `Make a plan to pay down $5,000 of debt within 12 months`, `pay off my credit card in 6 months`. A goal is either *save up* or *pay down*; the card shows the plan ("about $417 a month ($97 a week) until September 2027") before you save it, and payments toward a debt goal are logged under Debt.
- Reminders: `remind me to pay rent on the 1st at 9am`, `remind me to log receipts every evening at 8`, `recuérdame mañana a las 10 llamar al banco`. Time, day and repeat (once, daily, weekly, monthly) are pulled out; the rest is the reminder text. Reminders are local notifications, so the first one asks for permission and the card explains what to allow if it was refused. They live under Settings → Reminders.
- Several expenses at once: `I spent $67.99 at Macy's and $121.53 at Fleming's Steakhouse` or `Lunch was 12. Then 40 on gas and 4 for coffee.` are split into one entry each (on `and`, commas, `then`, sentence breaks, and their equivalents in every pack). A verb or date said once carries across the list. The confirmation card shows one editable row per entry and saves them together.
- Unknown places still work: `Spent $32 at Joe's` becomes a $32 expense with the note "Joe's" in *Other*, with a hint to tap the category and change it. The correction is learned for next time.

Every parse produces a confidence and plain hints ("Not sure about the category. Tap it to change."). Nothing is saved without the confirmation card.

**Tier 2 (optional, held back from 1.0 by `SMART_ASSIST`)**: if the user turns on *Smart parsing assist* in Settings and adds their own Anthropic API key, a low-confidence phrase is sent to the API with a strict JSON schema. It runs with an 8-second timeout and any failure (offline, bad key) falls back to "review manually". Off by default; nothing leaves the device unless the user opts in.

**Learning**: when the user changes the category on the confirmation card, the meaningful words of the phrase are stored in `keyword_mappings` and take priority next time. They can be reviewed and removed under Settings → Learned words.

## Importing statements and credit reports

Settings → Import a statement takes a PDF from a bank, a card issuer or a credit bureau, or a CSV export from a bank or card, and reads it on the device (pdf.js in a sandboxed WebView on the phone, in the page's own worker on the web). Nothing is uploaded. The pure parsing lives in `src/statements/`:

- **Bank and card statements.** Each transaction line becomes an entry with the right sign: from the header row's columns when the PDF has them (Deposits / Withdrawals / Balance), else from section headings, running-balance changes, minus signs, parentheses and CR/DR markers. Years are inferred from the statement period, so the December lines of a January statement land in December. Every line is categorized with the app's own vocabulary plus a statement-merchant dictionary (payroll, Walmart, Shell, Netflix, PG&E, CVS, card autopay …), and the user's learned words win. Transfers between the user's own accounts and card payments seen from the card side are unticked by default; refunds become income; interest and fees go to Debt. Lines already in the history are recognized by fingerprint and skipped. The review screen groups lines by month with money in / money out per month, lets the user change any category or drop any line, and only then saves. Changing a category teaches the merchant for next time. A card statement also records the card (balance, minimum payment, limit, APR) as a debt.
- **Credit reports.** Each account becomes a debt with creditor, type, balance, monthly payment, limit and rate. Settings → Debts & pay-off plan lists them and builds a plan for consumer debt only (cards, personal and student loans, lines of credit; mortgages and car loans are shown but left out): highest-rate-first when rates are known and differ, otherwise smallest-balance-first, with months to pay off and total interest for the extra amount the user can put in. Any debt can become a pay-down goal.
- **CSV exports.** The same parser reads a CSV download from a bank or card (`src/statements/csv.ts`): columns are found by header words in all eight languages or by the shape of the cells, amounts in any locale's notation, money in and out split by sign, by separate columns or by CR/DR flags, with a card export (charges positive, payments negative) recognised by its payment lines.
- **Nothing sensitive is kept.** The file is read once and deleted; only the approved entries remain (date, amount, category, cleaned merchant name). Account numbers, card numbers (even the last four digits), routing numbers and IBANs are stripped before anything is shown or saved, and the import history keeps no file name.
- **Limits.** Scanned PDFs (pictures of pages) have no text and are reported as such. Files are capped at 25 MB and 300 pages.

## Security

No server, no account, no bank link, no analytics. Every trust boundary (typed or spoken entries, imported backups, Smart Assist replies, the web build's browser sandbox) is validated and covered by attack-style tests in `__tests__/security.test.ts`, following the OWASP Mobile Top 10 and MASVS. Optional app lock with Face ID / fingerprint / passcode, Android cloud backup off, HTTPS only, and a strict Content-Security-Policy on the web build verified in headless Chromium (`npm run check:web-security`). Details: [docs/SECURITY.md](docs/SECURITY.md).

## Data

SQLite schema in `src/db/database.ts`, versioned with `PRAGMA user_version` and applied by `MIGRATIONS` (v16 today; each step is listed there and never edited afterwards). Tables: `transactions`, `categories` (with a `kind` column, optional `monthly_limit` and what happens to the unspent part at period end), `recurring_rules`, `goals` (`kind` is `saving` or `debt`), `reminders` (text, due time, repeat, scheduled notification id), `settings` (single row), `keyword_mappings`, `carryovers` (answers to "carry it over?"), `app_state` (small non-user state: recent voice lines, the trial's first and latest day, the unlock flag; never backed up).

Budget periods are calendar months unless Settings → Budget period is set to *My paydays*: then a period runs from one payday to the day before the next, with paydays taken from the active repeating income rules (a three-paycheck month simply has three periods). Category limits, the optional overall plan on the Budget tab, and roll-over all apply per period. Each category with a limit chooses what happens to the unspent part when the period ends: start fresh, carry it over to the next plan, or ask (a quiet card on Today). Only money that was not spent carries; going past a plan never takes from the next one. Removing an entry shows no dialog; an Undo bar puts it back.

A voice can talk back after each saved entry (Settings → Voice): Plain is the default and says nothing; Friend, Coach and Roaster add one line, with an attitude of Nice, Playful or Spicy. The engine in `src/lib/personas` knows the category, what is left of its plan and goal progress, so the line is useful as well as fun ("$20 at Starbucks? $43 left in Dining out."). It never comments on rent, bills, groceries, health, debt or other necessities, says nothing once a plan is exceeded, is always nice about large amounts, and only teases dining, entertainment, shopping and subscriptions at full strength. Onboarding asks once whether you want a voice and lets you pick a female or male spoken voice and a persona; Settings → Voice changes it any time, as does tapping the line under a saved entry, or simply saying "switch to the coach", "male voice", "be nicer" or "plain voice" on the Today tab (spoken switching is English only for now). Lines are English for now; other app languages keep the plain voice.

Screens keep to numbers and key words; the full sentences are for the voice. Today's card is one big number for what is left, in and out, and a spending bar (the biggest categories as segments of a single hue, names underneath), a "safe to spend until payday" line when the period has income (income minus spending minus repeating bills still due), and on Sunday and Monday a plain recap of last week compared with the week before. Headline sentences are set in Fraunces; totals count up and progress bars settle unless the phone asks for reduced motion. Settings → Appearance offers four accent colors.

Recurring rules are caught up on every launch and whenever a rule is saved: every due occurrence up to today is inserted as a transaction flagged `is_recurring_instance`, and `next_occurrence` moves forward. Monthly rules keep their day-of-month anchor (the 31st becomes the 28th in February and returns to the 31st in March).

Backups: CSV (entries), a readable text summary, a full JSON backup, and a passphrase-encrypted backup (scrypt + XChaCha20-Poly1305). Restore accepts either JSON form and replaces everything on the device after confirmation.

## Monetization

Free to install, the whole app for 30 days, then one one-time purchase through the store (`src/lib/trial.ts`, `src/lib/purchases.ts`). After the month, everything already entered stays readable, askable and exportable; only adding new things waits for the purchase. No subscription, no renewal, no ads, and nothing a person entered is ever behind the paywall.

## Status

Everything in the v1 must-have list is implemented, in eight languages: voice + text entry, Tier 1 parser with learning, confirmation card, default + custom categories with optional limits and roll-over, an optional overall plan, budgeting by calendar month or by payday, undo after removing an entry, an optional voice that talks back (English), recurring entries, monthly overview, goals with plain-language pace, CSV/summary/JSON/encrypted export and restore, full offline operation, onboarding without sign-up, light/dark theme, optional daily reminder. Tier 2 assist is implemented behind an opt-in.

Not built (v1.5 candidates): household sharing between two devices, home-screen widget, multi-currency entries, trend charts. The non-English copy was written in one pass and should get a native-speaker review before release.

Verified in this environment: unit tests, TypeScript, and a Metro/Hermes bundle. Not verified here: running on a physical device or simulator (no macOS/Android toolchain in the build container). Do that first with `npx expo run:ios` / `run:android`, and test voice on a real device since simulators have no on-device recognizer.
